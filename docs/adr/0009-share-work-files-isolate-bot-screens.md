# Share work files, isolate Bot Screens, keep application behavior native

Status: accepted on 2026-09-05. Runtime slices for Shared Workspace, Changes removal, on-demand Cage, projection lifetime, and selected-view measurement have landed; mandatory human host acceptance remains open.

Omarchy Bot is an Omarchy plugin inspired by Grok Bot's teammate model: users create Bots backed by installed Agents, all Bots share work files, and each Bot can continue its own desktop work while the client views another Bot. We retain on-demand, pure-headless Cage Bot Desktop Sessions with independent windows and input rather than full Omarchy sessions or one shared input seat; switching a Screen Projection changes observation, not the lifetime or ownership of background work. This preserves parallel desktop operation without making every Bot a separate computer, while resource acceptance must distinguish plugin overhead from Agent/application workloads and test selected-view use rather than assume simultaneous video streaming is the normal cost.

The plugin owns the Shared Workspace's default location and its own desktop lifecycle, capture, input routing, and per-Screen human handoff. Agents and applications own their work-file coordination and application behavior: neither file/task locks, Git worktree management, nor browser/profile/Cookie/login-sharing policy is part of this desktop contract. Shared work files survive Bot deletion, the plugin checkout is not the default work directory, and Changes is removed from the product rather than replaced with an unrequested review or artifact panel.

## Authority and supersession

- [The product boundary](../workspace-redesign.md#shared-workspace-and-plugin-boundary) defines the directory, ownership relationships, lifecycle requirements, and implementation gaps. Its Computer section defines the required host-safety and resource evidence.
- [Computer ADR 0008](../contexts/computer-control/adr/0008-run-cage-bot-desktops.md) remains the compositor/transport choice. This decision clarifies on-demand session lifetime and supersedes treating per-Bot application profiles as a product requirement or historical capacity passes as proof of current host safety and acceptable normal-use cost.
- The Changes capability and daemon-cwd fallback in [the capability-panel spec](../../.scratch/workspace-capability-panel/spec.md) are superseded. Unrelated Composer improvements remain in [the product boundary](../workspace-redesign.md#7-composer) and [the current implementation specification](../../.scratch/shared-workspace-desktop-boundary/spec.md). Mixed and historical sources are accounted in [the requirement map](../../.scratch/shared-workspace-desktop-boundary/requirement-map.md).
- [Bot deletion ADR 0006](./0006-bot-deletion-is-local-only.md) remains in force; Shared Workspace files, like Agent-owned Native Sessions, are outside Bot deletion. Existing application state must not be migrated, synchronized, or erased merely to conform to this documentation update.
