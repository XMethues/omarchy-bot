# Prompt-authored and uploaded Bot avatars

A Bot Profile supports both locally uploaded images and animated DiceBear avatars. Newly created Bots receive a deterministic generated avatar; the profile editor lets the user upload an image, choose another generated variation, or describe a new avatar with a prompt. It also identifies the Bot's immutable Agent so the user knows which Agent performs prompt-to-recipe generation.

For prompt generation, the Bot's selected Agent returns a constrained Avatar Recipe containing supported DiceBear options. Omarchy Bot validates the recipe and renders the SVG itself. Agent-produced SVG, HTML, scripts, and remote image URLs are never rendered directly. The prompt-generation turn is a profile operation, not a Thread message.

Generated avatars may use their native restrained animation while the Bot is selected or working. Uploaded avatars receive only a shared container-level activity treatment so both sources communicate the same state. In the transcript, the active assistant avatar may animate while output is streaming and settles when the turn completes. Reduced-motion mode replaces movement with a static state indicator.

Consequences: avatar uploads are re-encoded and stored locally. Every generated Avatar Recipe stores a lossless renderer identity, style, seed, and validated options. Newly generated recipes use exactly `dicebear-core@10.7.0+styles@10.6.0` and DiceBear's native `animationVariant`; legacy recipes with renderer identity `9.4.3` keep their deterministic legacy rendering and are never rewritten during migration or display. A legacy recipe changes renderer only through an explicit user-requested variation or prompt regeneration, which stores a new current recipe rather than mutating the legacy recipe in place. Animation must never run continuously for every Bot or move message content itself. Every meaningful Bot avatar has an accessible label derived from the Bot name; purely decorative duplicate avatars are hidden from assistive technology.
