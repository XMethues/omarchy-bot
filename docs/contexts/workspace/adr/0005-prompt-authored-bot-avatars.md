# Prompt-authored and uploaded Bot avatars

_The activity-state and avatar-motion portions of this decision are superseded by [system ADR 0005](../../../adr/0005-bot-activity-is-binary.md). The avatar recipe, renderer, upload, and safety decisions remain current._

A Bot Profile supports both locally uploaded images and animated DiceBear avatars. Newly created Bots receive a deterministic generated avatar; the profile editor lets the user upload an image, choose another generated variation, or describe a new avatar with a prompt. It also identifies the Bot's immutable Agent so the user knows which Agent performs prompt-to-recipe generation.

For prompt generation, the Bot's selected Agent returns a constrained Avatar Recipe containing supported DiceBear options. Omarchy Bot validates the recipe and renders the SVG itself. Agent-produced SVG, HTML, scripts, and remote image URLs are never rendered directly. The prompt-generation turn is a profile operation, not a Thread message.

Active generated avatars combine their native restrained animation with a shared container-level breathing treatment so motion remains legible at workspace avatar sizes; active uploaded avatars use only the shared treatment. Selected, working, and streaming states use progressively faster motion, while idle avatars remain static. In the transcript, the active assistant avatar may animate while output is streaming and settles when the turn completes. Reduced-motion mode replaces all movement with a static state indicator.

Consequences: avatar uploads are re-encoded and stored locally. Every generated Avatar Recipe stores the current renderer identity, style, seed, and validated options. The application supports exactly `dicebear-core@10.7.0+styles@10.6.0`, retaining Shapes alongside the Bot-profile styles Clay, Critters, Gaze, Initial Face, Moods, Pixelbot, Sprouts, Thumbs, Voxel Art, and Voxel Bot so existing profiles keep their identity. Unsupported recipes become deterministic Pixelbot defaults rather than keeping compatibility renderers. Supported generated avatars use DiceBear's native `animationVariant`. Animation must never run continuously for every Bot or move message content itself. Every meaningful Bot avatar has an accessible label derived from the Bot name; purely decorative duplicate avatars are hidden from assistive technology.
