# Adopt private Sway Bot Desktop Sessions

Status: accepted on 2026-09-06. Production cutover completed on 2026-09-07. Cage production implementation removed on 2026-09-07 (ticket 11).

The production Bot Desktop Runtime Stack is one pure-headless Sway session per newly provisioned Bot Desktop Session, WayVNC for on-demand **view-only** RFB projection, the existing Computer Broker-authorized input path for human keyboard, pointer, and paste actions, and a native Sway IPC adapter for truthful window enumeration and focus. WayVNC remote input and clipboard are disabled so an RFB client cannot become a second input seat that bypasses controller epochs, ordering, stale-generation rejection, held-input release, or Takeover. Every Bot receives private runtime, Wayland, Sway IPC, VNC, D-Bus, and application-profile endpoints; the stack never attaches to the Host Session or its physical input. A graphical Bot action or opening the Computer Surface provisions or resumes the desktop. Closing a Screen Projection releases that viewer and unused capture/transport work without stopping unfinished graphical work or destroying live application state. Only an explicit destructive stop ends Sway and its applications.

Ticket 09 recorded `cutover: go`. Production `main()` constructs `SwayBotScreenRuntimeAdapter` exclusively for every newly provisioned Bot Desktop Session. There is no compositor selector and no automatic Cage fallback. Live leftover Cage trees under the Bot Screen runtime root block production start until they exit or an explicit one-shot `OMARCHY_BOT_DESTROY_LEFTOVER_CAGE=1` teardown runs; that helper is migration safety, not a Cage runtime. Human Host Session acceptance remains pending ([checklist](../../../.scratch/sway-bot-desktop-runtime/host-session-acceptance.md)); do not treat automated isolation as a human pass.

Sway was chosen after correctness and isolation, similarity to Omarchy, and total resource cost were considered in that order. It is the closest independently runnable, already-exercised Wayland/wlroots option. Xvnc with IceWM is a contingency rather than a second supported runtime: its mature EWMH control and connection-independent session lifetime are useful, but the inspected Agent backend falsely reported successful Chinese input while producing incorrect text. Xfce adds desktop/session processes and packaging assumptions without removing that blocker. Private Hyprland remains ineligible until reliable pure-headless startup is proved without using the Host Session. Any contingency promotion requires revisiting this decision rather than silently adding another runtime path.

Evidence and bounded claims are recorded in [the lightweight runtime comparison](../../../research/lightweight-bot-desktop-runtimes.md) and [the Wayland backend research](../../../research/wayland-computer-use-backends.md).
